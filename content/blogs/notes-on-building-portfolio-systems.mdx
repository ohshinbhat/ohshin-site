A portfolio is a product with a different feedback loop.

The content changes more often than the layout. New projects appear. Old work becomes less relevant. Writing accumulates. Contact details move. If every one of those changes requires touching React components, the site becomes expensive to maintain for the wrong reasons.

## The principle

Push content out of the rendering layer.

That means:

- structured files for repeated content like projects and work history
- one content loading layer on the server
- validation so broken content fails loudly
- presentation components that do not know where the data came from

## Why this matters

The real cost of a portfolio is not deployment. It is update friction.

If updates feel heavy, the site stops reflecting reality. Once that drift starts, the portfolio gets less useful with every month you avoid editing it.

## A better default

Git-backed JSON and MDX are usually enough.

They are easy to diff, easy to migrate, and easy to wrap with a CMS later if the editing workflow changes. That keeps the architecture stable while the content model evolves.
